# Module planning and Overview backend contract

The updated Module settings and Overview PNGs supplement the original design. This is backend work only.

- Module persists `plannedLectureCount: Int`, date-only Gregorian `examDate: ExamDate?`, and `archivedAt: Date?` (`isArchived` computed). Old module JSON defaults to its imported lecture count, no exam, active. Imports grow the plan automatically when necessary. Settings cannot reduce the plan below the latest imported count; 10,000 is the defensive maximum to prevent unbounded slot allocation from malformed backup/settings input. The generic metadata/order update preserves the latest planning fields; only the narrow settings API changes them.
- Archive/unarchive is explicit and reversible. Archived modules are excluded from Overview and its totals. All contents remain readable; Anki/PDF/backup export remains available. Export marks are the sole user-facing write exception. All other module/lecture edits, new imports, restores into that existing module, and AI enqueue/retry are blocked by the store. Archive refuses a module with durable running/queued jobs; users must wait or cancel and await idle first. A preparation racing archive must fail before inference. Do not delete data or silently cancel paid work.
- Progress is pure derived state, computed from an atomic store snapshot. Use the same result for Overview, module rows, and sidebar. Source pages are one based, slide indices zero based.
- Each imported lecture occupies its module-order slot; append empty slots until planned count. No placeholder lecture records. Slots have stable identity from module UUID + one-based slot index.
- Ignore superseded cards. Review count is a union per card: Unreviewed, Needs adjustment, an unresolved proposal (any state), or a Good card that fails `lecture.issues(for:)`. Bad cards without proposals are resolved rejection. AI flags alone do not undo approval.
- Ready-to-export count uses the existing Anki eligibility rule: Good, valid, not superseded, never exported or current revision differs from export mark. Changed count is its previously-exported subset. Count proposals separately, without counting their card twice as review work.
- Coverage uses `lecture.coverage(page:)` for every selected page, so rejected/superseded cards do not cover slides. A PDF lecture with zero selected pages or a sourceless lecture with zero cards has no work yet and cannot be Done. A sourceless legacy lecture with reviewed cards can complete without fabricated sources. Running jobs prevent Done.
- Status precedence: To review if review work exists; otherwise Preparing if coverage/no-work/running-job blockers exist; otherwise To export if eligible cards remain; otherwise Done. This exactly enforces “selected slides carded, every card reviewed, approved cards exported.” Empty planned slots are Not imported. Reopening cards/selection/export revisions changes progress immediately.
- Dashboard returns active module progress, archived module metadata/count, global done/planned/review-card/review-lecture/proposal/ready-export/changed-export/not-imported totals. Archived modules contribute to none of those totals.
- Module progress returns ordered lecture progress, slots, status counts, and a deterministic Next up list (maximum 3): first lecture needing Review; module Export with all exportable lecture IDs/count; first Preparing lecture; first empty Import slot. Include typed actions/IDs and reasons, no preformatted navigation strings. Preparation reasons: select slides, generate missing coverage, waiting for jobs, or add cards.
- Pace: `remainingLectures = planned - done`, days from local Gregorian start of today to date-only exam; future `lecturesPerWeek = remaining * 7 / days`, exact fractional weeks. Distinguish no exam, future, due today, overdue, and complete. No infinity, negative rate, or automatic archive. Caller injects clock/time zone for deterministic tests. UI owns date/number formatting.

Acceptance: old JSON compatibility; invalid dates/plans; current-count race on save/import; backward/forward progress transitions and no vacuous Done; exact global totals and module order; incomplete coverage/Bad/split/invalid/proposal/export handling; date boundaries/DST/overdue/no date; archive mutation enforcement, export/unarchive, running job/preparation race; archived backup round-trip. Update frontend handoff and verification after tests and independent Sol 6.1 medium review.
